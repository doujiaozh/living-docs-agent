# 📚 living-docs-agent

> Let your README never go stale — documentation that regenerates itself while you code.

**living-docs-agent** is a zero-dependency Node.js CLI that scans C / Python source directories, extracts function signatures, comments, parameters and return types, and emits beautiful Markdown API docs — optionally injected directly between markers in your README. Run it once, or run it with `--watch` and your docs update the moment you save a file.

- 🪶 **Zero dependencies** — plain Node.js ≥ 18, nothing to install
- 🔍 **Real parsing** — Python docstrings (reST + Google style), Doxygen comments, multi-line signatures, type inference, `*args`/`**kwargs`, decorators, static/C keywords
- 💉 **Marker injection** — docs live inside your README between livedocs start/end marker comments, so prose and API reference stay in one file
- 👀 **`--watch` mode** — debounced, cross-platform polling; regenerates only when source actually changes
- ✨ **Beautiful output** — shields.io badges, GitHub-compatible anchors, parameter tables, source links

## 🚀 Quick start

```bash
# Generate a standalone API document
node bin/cli.js ./src -o docs/API.md --title "My Library"

# Inject (and keep updating) the API section inside README.md
node bin/cli.js ./src -r README.md

# Watch mode: regenerate on save
node bin/cli.js ./src -r README.md --watch
```

### Options

| Option | Meaning |
| ------ | ------- |
| `<src>…` | One or more source directories (repeatable) |
| `-o, --output <file>` | Write standalone Markdown to a file |
| `-r, --readme <file>` | Inject the API section into a README between markers |
| `-w, --watch` | Watch sources and regenerate on change |
| `--lang <c\|python\|auto>` | Force a language or auto-detect per directory (default) |
| `-t, --title <text>` | Document title (default `API Reference`) |
| `--no-toc` | Skip the table of contents |
| `--interval <ms>` | Watch poll interval (default 500) |
| `-h, --help` / `-v, --version` | Help and version |

### Marker injection

Add these comments to your README — they must each be on their own line — and the CLI will keep everything between them fresh:

```markdown
<!-- livedocs:start -->
<!-- livedocs:end -->
```
